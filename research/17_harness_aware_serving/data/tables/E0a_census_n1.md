## 1. Usage semantics (checked)

vLLM 0.31's Anthropic endpoint reports `input_tokens = prompt - cache_read - cache_creation`, where `cache_creation` counts the tokens computed and written to the prefix cache (full blocks). Every `cache_read` below is a multiple of the block (16 tokens; 256 for DeepSeek-V4's `--block-size 256`; 784 for Qwen3.8's hybrid state checkpoints), and `input_tokens` stays below one block in (almost) every call: it is the computed tail that fills no block. So P = input + cache_read + creation (as `cache_snip.py`) and computed U = input + creation.

## 4. Validation of the edit estimate against topic 16's measured alignments

Truth per call: `reuse_avail - exact` from the plan (tokens of the previous prompt + reply that the call reuses after the first divergence; what a prefix cache recomputes because of the edit) and `edited`. EPIC arms: every lead call of the 168 main EPIC-arm runs, priced as vanilla prefix caching (U = P - E). Prefix arms: the 30 recorded prefix runs replayed by E-A (main, screen, pilot; their first 80 calls), with U = the server's own computed tokens (its cache can serve more than the exact prefix from older sequences, or less after an eviction).
