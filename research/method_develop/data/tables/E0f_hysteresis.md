## 3. What it means for D1 at N = 1

- As run (rolling snip): edit work is 10.0 % of the lead chain's modeled time over all 86,643 lead calls; 12 of 12 model x bench cells reach 5 %. Calls with an edit: 75.2 %.
- With snip hysteresis: 0.7 % (calls with an edit 9.3 %; edit tokens 0.07 x of as run); 0 cells reach 5 %.
- Edit work removed by the harness fix alone: 93.9 % of the as-run edit work; total modeled lead time -9.9 %. Largest cell under hysteresis: qwen3-32b / swe 2.3 %.
- At N = 1 the GPU is busy only during the chain's calls, so GPU time is the same sum and D1's GPU-time criterion (>= 20 %) reads the same shares: it fails in both arms (10.0 % / 0.7 %).
- D1 at N = 1 therefore passes as run but not under the harness-fixed counterfactual: here the harness fix (snip hysteresis) is the cheaper remedy, unless an N > 1 cell (E0a) still passes with it.

## 4. Checks

- The rolling arm, replayed from the logical message stream alone, reproduces the logged request in 85,507 of 85,507 transitions (100.0 %); 20 transitions after an overflow + reactive summary continue from the logged request in both arms.
- Trials: 1,116 (failed: 0). Subagent / summary calls (sensitivity column, served tokens from usage): 989 / 102.
- Prompts beyond 32,768 tokens (outside the TTFT model's fit, extrapolated), as run: qwen3.8-27b 12.9 % of calls, 35.1 % of edit work; deepseek-v4-flash 10.4 % of calls, 32.1 % of edit work; minimax-m2.7 8.0 % of calls, 22.3 % of edit work.
- First order: replies, tool results and summaries are the as-run ones; the model would have seen different contexts under hysteresis (between cuts it sees up to 50 messages, right after a cut 30), so trajectories, lengths and tool calls would change. The TTFT model is fit on Qwen3-32B (H100) and is extrapolated beyond its measured contexts for the 128K-window models; the TPOT table ends at 30K context (flat beyond), which understates decode time at long contexts and so overstates edit shares there.
